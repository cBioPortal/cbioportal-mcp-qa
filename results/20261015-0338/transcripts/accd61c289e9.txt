Q (haiku-5.5): what's the best way to put clinical data into cbioportal?

═ answer (success)
The most reliable route is to format your data as a **cBioPortal study folder** (tab-delimited files plus metadata files), validate it with the official validator, and then load it into a local instance or submit it for hosting. I'm answering from the documented format rather than checking the live database, so confirm details against the current spec at docs.cbioportal.org (File Formats and Study Preparation).

**1. Split clinical data into two files**
- `data_clinical_patient.txt`: one row per patient. `PATIENT_ID` is required.
- `data_clinical_sample.txt`: one row per sample. `PATIENT_ID` and `SAMPLE_ID` are required. `SAMPLE_ID` must match the IDs used in your mutation and CNA files.

**2. Use the four-line header**
1. Column names (e.g. `PATIENT_ID`, `AGE`, `SEX`)
2. Human-readable description
3. Data type: `STRING`, `NUMBER`, or `BOOLEAN`
4. Priority (an integer that controls display order)

**3. Use standard names for common fields**
- Survival needs paired `_MONTHS` and `_STATUS` columns, with status written as `0:LIVING` / `1:DECEASED`. Without these, Survival tabs won't work.
- Use standard names such as `CANCER_TYPE`, `CANCER_TYPE_DETAILED`, and `SAMPLE_TYPE` where they apply, so the portal can filter on them.
- Keep attribute IDs uppercase with underscores and no spaces.
- Use blank or `NA` for missing values, and keep one value type per column.

**4. Add metadata files**
- `meta_study.txt`: study ID, name, cancer type, description, citation.
- `meta_clinical_patient.txt` and `meta_clinical_sample.txt`: declare each data file, with `genetic_alteration_type: CLINICAL` and `datatype: PATIENT_ATTRIBUTES` or `SAMPLE_ATTRIBUTES`.
- `case_lists/`: lists of sample IDs, including a `cases_all` file.

**5. Optional: timeline data**
Treatments, specimen events, and similar items go in separate timeline files (`data_timeline_*.txt`) with start and stop dates, not in the clinical files.

**6. Validate before loading**
Run the `validateData.py` script on the study folder. Fix every error before importing, since it catches header, ID-matching, and format problems.

**7. Load or submit**
- **Local or private instance:** import with the cBioPortal importer scripts (`metaImport.py` or the importer used by your deployment).
- **Public cBioPortal.org:** submit through the cbioportal-datahub GitHub process or contact the cBioPortal team. Their studies follow this same format.

**Practical tips**
- Start from an existing study in the cbioportal-datahub repository and modify it. This is faster than writing headers and metadata from scratch.
- Build the files from a script (R or Python) from your source data rather than editing them by hand, so re-exports stay consistent.
- Check whether your institution has an internal process for releasing clinical data before loading it anywhere shared.
