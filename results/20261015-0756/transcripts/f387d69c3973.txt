Q (haiku-5.5): what's the best way to put clinical data into cbioportal?

═ answer (success)
The best route depends on whether you're loading into a local cBioPortal instance or submitting a study for the public portal. In both cases the work is in the file format, and the import tooling validates it.

**1. Prepare the clinical files**

A study needs two clinical files, one per level:
- `data_clinical_patient.txt`: one row per patient (e.g., `SEX`, `AGE`, `OS_MONTHS`, `OS_STATUS`).
- `data_clinical_sample.txt`: one row per sample (e.g., `ONCOTREE_CODE`, `SAMPLE_TYPE`), with `PATIENT_ID` linking back to the patient file.

Each file starts with four header lines, followed by a column-name line and then the data:

```
#Patient Identifier	Sex	Overall Survival (Months)	Overall Survival Status
#Patient identifier	Sex of the patient	Overall survival in months	Overall survival status
#STRING	STRING	NUMBER	STRING
#1	1	1	1
PATIENT_ID	SEX	OS_MONTHS	OS_STATUS
P001	Female	34.2	0:LIVING
```

The `#datatype` line must be `STRING`, `NUMBER`, or `BOOLEAN`. Use tab-separated values and no spaces in the column names.

**2. Add a meta file for each data file**

`meta_clinical_patient.txt` and `meta_clinical_sample.txt` tell the importer what each file is:

```
cancer_study_identifier: my_study_2026
genetic_alteration_type: CLINICAL
datatype: PATIENT_ATTRIBUTES
data_filename: data_clinical_patient.txt
```

Use `SAMPLE_ATTRIBUTES` for the sample file.

**3. Follow the conventions that matter most**
- Use the standard attribute names where they exist (e.g., `OS_MONTHS`/`OS_STATUS`, `DFS_MONTHS`/`DFS_STATUS`, `AGE`, `SEX`). Standard names let the portal's survival and clinical views work automatically.
- Survival status uses the `0:LIVING` / `1:DECEASED` style, not free text.
- Cancer type should be an OncoTree code in `ONCOTREE_CODE`. Look codes up with the OncoTree site or the search tool here.
- Sample and patient IDs must match exactly across the clinical files and any mutation or CNA files.
- De-identify ages and dates before loading, and check the portal's own guidance on what is allowed.

**4. Validate and import**

- **Local instance:** Run the cBioPortal importer on the study folder. Its validator reports format and ID-matching errors before anything loads. The `cbioportal` GitHub documentation covers the exact command for your version (Docker or the Java/Perl importer).
- **Public portal:** Studies are submitted through the cBioPortal data hub on GitHub (a pull request with the files and meta files) and go through the same validation.

**For MSK:** If the data is internal, check with the MSK cBioPortal team about the institutional ingestion path before loading anything, because data-sharing and de-identification rules may apply.
