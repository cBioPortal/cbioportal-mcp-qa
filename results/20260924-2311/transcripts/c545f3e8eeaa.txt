# Treatment Data Query Guide

## Overview

Treatment data in cBioPortal is stored in **clinical event tables**, separate from clinical attributes. This allows for timeline-based treatment records with start/stop dates.

## Start Here: Treatment Views

For "most common treatments / agents / regimens in study X", use the parameterized views (documented in `cbioportal://clinical-data-guide`, Study-View Chart Counts):

```sql
-- Patients per agent (the portal's Treatment chart), with type/subtype arrays
SELECT * FROM treatment_counts_in_study(study='msk_chord_2024') ORDER BY patients DESC LIMIT 20;

-- Same-day agent combinations (investigational, prior-medication and radiation events excluded)
SELECT * FROM treatment_regimens_in_study(study='msk_chord_2024') ORDER BY patients DESC LIMIT 20;
```

Write raw event queries (below) only for subgroups, timelines or keys the views do not expose.

## Key Tables

| Table | Description |
|-------|-------------|
| `clinical_event` | Event records with patient_id, event_type, start_date, stop_date |
| `clinical_event_data` | Key-value pairs linked to each clinical_event_id |

## Schema

```
clinical_event
├── clinical_event_id (PK)
├── patient_id (FK → patient.internal_id)
├── event_type (Treatment, TREATMENT, Diagnosis, SURGERY, etc.)

└── stop_date (days from diagnosis)

clinical_event_data
├── clinical_event_id (FK)
├── key (AGENT, SUBTYPE, etc.)
└── value
```

Note that querying "the timeline files" directly (as raw TSVs) isn't something this database exposes — cBioPortal ClickHouse stores timeline/clinical-event data relationally in `clinical_event` + `clinical_event_data`, joined via `patient` and `cancer_study`. That's the correct, reliable equivalent of the study's timeline files, and it's what the code below queries through the public cBioPortal REST API (so you don't need direct database credentials).

Below is Python code using the public cBioPortal API (`https://www.cbioportal.org/api`) to pull all clinical timeline events for MSK-CHORD (`msk_chord_2024`), reshaping them into a pandas DataFrame similar to the portal's timeline files (`PATIENT_ID`, `START_DATE`, `STOP_DATE`, `EVENT_TYPE`, plus one column per data key).

```python
"""
Query clinical timeline data for the MSK-CHORD (msk_chord_2024) study
via the public cBioPortal REST API.

Requires: pip install requests pandas
"""

import requests
import pandas as pd

BASE_URL = "https://www.cbioportal.org/api"
STUDY_ID = "msk_chord_2024"


def get_all_patient_ids(study_id: str) -> list[str]:
    """Fetch all patient IDs in the study."""
    patients = []
    offset = 0
    page_size = 10000
    while True:
        resp = requests.get(
            f"{BASE_URL}/studies/{study_id}/patients",
            params={"pageSize": page_size, "pageNumber": offset // page_size},
        )
        resp.raise_for_status()
        batch = resp.json()
        if not batch:
            break
        patients.extend(p["patientId"] for p in batch)
        if len(batch) < page_size:
            break
        offset += page_size
    return patients


def get_clinical_events(study_id: str, patient_ids: list[str],
                         event_types: list[str] | None = None,
                         chunk_size: int = 500) -> pd.DataFrame:
    """
    Fetch clinical timeline events for a list of patients, in chunks
    (the API's clinical-event-data fetch endpoint takes a patient list).

    event_types: optional list to filter, e.g. ["TREATMENT", "SPECIMEN", "STATUS"]
                 If None, all event types are returned.
    """
    all_rows = []

    for i in range(0, len(patient_ids), chunk_size):
        chunk = patient_ids[i:i + chunk_size]
        payload = {"ids": chunk}

        resp = requests.post(
            f"{BASE_URL}/studies/{study_id}/clinical-events/fetch",
            json=payload,
            params={"projection": "DETAILED"},
        )
        resp.raise_for_status()
        events = resp.json()

        for ev in events:
            if event_types and ev["eventType"] not in event_types:
                continue
            row = {
                "PATIENT_ID": ev["patientId"],
                "EVENT_TYPE": ev["eventType"],
                "START_DATE": ev["startDate"],
                "STOP_DATE": ev.get("stopDate"),
            }
            # attributes is a list of {"key": ..., "value": ...} pairs
            for attr in ev.get("attributes", []):
                row[attr["key"]] = attr["value"]
            all_rows.append(row)

        print(f"Fetched events for patients {i + 1}-{min(i + chunk_size, len(patient_ids))} "
              f"of {len(patient_ids)}")

    return pd.DataFrame(all_rows)


if __name__ == "__main__":
    print(f"Retrieving patient list for {STUDY_ID}...")
    patient_ids = get_all_patient_ids(STUDY_ID)
    print(f"Found {len(patient_ids)} patients.")

    # Example: pull only Treatment and Diagnosis (e.g. NLP progression) events.
    # Set event_types=None to pull the full timeline (all event types).
    df = get_clinical_events(
        STUDY_ID,
        patient_ids,
        event_types=["TREATMENT", "Treatment", "Diagnosis"],
    )

    print(df.head())
    print(f"\nTotal events retrieved: {len(df)}")
    print("\nEvent type counts:")
    print(df["EVENT_TYPE"].value_counts())

    df.to_csv("msk_chord_2024_timeline_events.csv", index=False)
    print("\nSaved to msk_chord_2024_timeline_events.csv")
```

**Notes specific to MSK-CHORD:**
- Event types include `Treatment`/`TREATMENT`, `Diagnosis` (includes NLP-derived radiology progression events, `SUBTYPE = 'Progression'`), `SURGERY`, `Sequencing`, `Sample acquisition`, among others — check casing, as it's inconsistent within the study.
- `START_DATE`/`STOP_DATE` are in days from diagnosis, not calendar dates.
- Treatment events carry keys like `AGENT`, `SUBTYPE`, `TREATMENT_TYPE`, `RX_INVESTIGATIVE`, `INFERRED_TX_PROB` (NLP confidence) — these appear as extra columns in the DataFrame.
