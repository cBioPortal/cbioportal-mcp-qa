I can't confirm that any study has a `data_clinical_outcomes.txt` file. The cBioPortal database I can query only holds the loaded data, so it doesn't record source file names, and `data_clinical_outcomes.txt` isn't one of the standard cBioPortal clinical file names. The standard clinical files are `data_clinical_patient.txt` and `data_clinical_sample.txt`. Their meta files declare `data_filename` and `datatype`, such as `PATIENT_ATTRIBUTES` or `SAMPLE_ATTRIBUTES`. Your file may be a custom or institution-specific split.

If it is a patient-level file with outcome columns, it would be loaded as clinical attributes. These studies are good models for that:

- **MSK-CHORD 2024** ([`msk_chord_2024`](https://www.cbioportal.org/study/summary?id=msk_chord_2024)): about 25k samples and 24,950 patients across lung, colorectal, breast, prostate and pancreatic cancers. It has overall survival (`OS_MONTHS`, `OS_STATUS`). It also has timeline data for treatments and NLP-derived progression events, which are loaded as clinical events rather than from a clinical attribute file. It is the richest MSK example of outcomes plus treatment.
- **TCGA PanCancer Atlas studies** (for example `luad_tcga_pan_can_atlas_2018`): these have OS, DFS, PFS and DSS, each with a status and a months column, in the patient file. They are a clean, standard layout to copy.

To find the real file layout, open the study's folder in the public repository at https://github.com/cBioPortal/datahub and look for the `meta_clinical_*.txt` files. Alternatively, run `ls` in the study directory if you have the files locally.
